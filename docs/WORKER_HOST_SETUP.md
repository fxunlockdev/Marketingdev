# Private trusted worker host

The worker requires a dedicated Linux amd64 host with a local Docker daemon. It is not a normal Railway web service: the existing application starts credential-free child containers for skills, documents, crawling and media rendering. Do not expose Docker over TCP or share this host with unrelated applications.

Build the application/worker with `node scripts/worker-image.mjs`. The worker extends the exact built API image, preserves its non-root Node user and adds the Docker 29.1.2 static client from the official amd64 image digest `sha256:21a1c55469066f188822c840c6524d53ee9839e22016d44ef7fbe33a9cd86d64`. That child digest was read from the official `docker:29.1.2-cli` OCI index (`sha256:d525718bb067b852a3a33c49485e5f5ac412be1e6e76f7551bdc202d5a889f85`). No daemon is installed inside the worker image.

Load exact amd64 images for the trusted worker, document parser, original skills, static renderer and video renderer into the dedicated host daemon. Set their local content digests as `DESVIO_WORKER_IMAGE`, `DOCUMENT_PARSER_IMAGE`, `SKILL_RUNTIME_IMAGE`, `RENDER_RUNTIME_IMAGE`, `VIDEO_RUNTIME_IMAGE`. Never substitute tags. Set the existing worker configuration from `workerConfigFromEnv`, using only the worker/dispatcher database logins, private Temporal/scanner/storage endpoints and separately authorized provider keys. Explicitly set `VIDEO_ENABLED`, `POSTIZ_ENABLED`, `POSTIZ_PUBLISHING_ENABLED` to true or false; initial deployment uses false. The control script validates existing model/encryption prerequisites when enabling a capability.

`node scripts/start-worker-host.mjs --check` validates configuration, all image architectures and any existing container identity without launching it. `node scripts/start-worker-host.mjs` creates/starts the fixed `desvio-trusted-worker` container. Environment values are inherited through an explicit allowlist, never interpolated into commands. Administrative/API/SMTP credentials are rejected. The script can run on the trusted host, or from the worker image with the local socket mounted and its socket group supplied. Its configuration hash and exact image are retained as labels; reruns refuse mismatched existing containers rather than replacing active jobs. Concurrent starts reconcile the fixed name. No credentials or raw Docker errors are printed.

The worker is non-root with a read-only filesystem, dropped capabilities, no-new-privileges, bounded CPU/memory/processes, temporary scratch space and `unless-stopped` restart policy. Host networking permits the trusted provider/database/Temporal connections. The private socket is intentionally powerful: the worker is trusted control-plane code, and host administrators can inspect its runtime environment. Customer code never executes in this container. Existing typed child launchers omit credentials, socket and host mounts and disable networking. Do not checkpoint a host after secrets have been supplied: Docker container metadata can retain runtime environment values. Build-only snapshots must be captured before runtime configuration.

Container running status is not job readiness. Acceptance still requires exact runtime-role authentication, Temporal worker registration, scanner freshness, private storage checks, a real job surviving worker/container replacement, tenant isolation and genuine provider calls when authorized. A host disappearing must be reconciled against its retained Railway sandbox ID before replacement; local restart policy does not prove Railway sandbox recovery. `make verify-worker-host` currently proves image packaging, configuration guards, source upload boundaries and a real credential-free child container only. Hosted lifecycle acceptance remains pending.

## Private dev host controller

The operator-only `infra/worker-control/` scripts target the existing Desvio dev project/environment explicitly. `host.mjs ensure` persists creation intent before provisioning and reconciles an existing host; it refuses automatic replacement of a terminal host. `bundle.mjs` exports only the five exact reviewed runtime image IDs. `transfer.mjs` uses a temporary private bucket object, sends its signed download URL via stdin, verifies bytes/SHA on the host and removes the temporary object. Image import is a separate durable Railway execution, whose session must be reconciled before repeating it.

`verify-host.mjs` checks imported IDs/architecture/users plus real clean-file acceptance, standard antivirus test rejection and fresh scanner signatures. `start-dev.mjs` reads the ignored mode-600 local role-password recovery file and Railway bucket credentials into memory, passes values through stdin and starts the guarded worker controller. No model keys or live provider grants are enabled. Never checkpoint this host after worker configuration: Docker container metadata contains runtime credentials. `check-registration.mjs` checks the two role logins and actual workflow/activity pollers; it does not imply successful customer jobs or recovery.

Actual host/image/scanner/start/registration evidence is recorded separately under `docs/evidence/railway-worker-*.json`. Full deployed tenant/job/browser acceptance remains required.

## Hosted component acceptance

`check-crawl.mjs` exercises actual robots-aware public fetching plus isolated desktop/mobile extraction/rendering on one simple page. It does not measure broad brand-analysis quality.

`check-job.mjs` creates explicitly labelled administrative fixture identities in dedicated dev, then calls real application service methods with the application database role to reserve a private PNG and submit its validation job. The real running dispatcher/Temporal worker scans and persists it. The script checks replay, unsigned/foreign denial and canonical/normalized checksums. It does not bypass verification for real users or claim browser/email acceptance.

`check-job.mjs --recovery` additionally verifies an idle worker, stops it, verifies the new job stays queued and undispatched for five seconds, and automatically starts the same container after 25 seconds or on finalization. Successful output includes the restored running state. It intentionally interrupts this dedicated dev worker; never generalize it to production or a shared host. It does not simulate host loss or a crash during a paid provider request.

After a successful run, use `check-job.mjs --cleanup` (or `--recovery --cleanup`) to require a completed workflow, verify exact fixture ownership, remove only its three objects and fixed scoped database rows, and retain normal Temporal history. Mode-600 manifests in ignored `work/` preserve IDs and prevent accidental repeated runs. Reconcile uncertain outcomes against the named container and manifest before any rerun. Administrator credentials enter only the separate temporary acceptance container through stdin, never the persistent worker, arguments, reports or logs.

Reports are `railway-worker-job.json`, `railway-worker-recovery.json` and their cleanup reports. Registration-only reports do not supersede these broader checks. Full authenticated customer, host replacement and authorized provider acceptance remain outstanding.
