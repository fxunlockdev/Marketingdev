# ADR 0040: evidence-bound analysis and approved learning

Reuse the existing original-skill sandbox, official OpenAI/Gemini text adapters, job dispatcher and Temporal worker. The new `insight.generate` job loads only the audited `analytics`, `ab-testing` and `product-marketing` skills. Their digests are generated from the verified 52-skill inventory. Only the existing allowlisted read_file broker is available; no imported helpers, networking, delegation, publishing or provider credentials enter the sandbox.

Requests snapshot approved brand facts and at most 20 confirmed published posts whose latest metrics observation is available. Each observation retains its ID, post identity, caption, provider, format, measurement semantics and collection time. Missing/error data is excluded, never zero-filled. The input hash and selected provider/model are immutable. A separate expiring operator grant and provider-specific ledger authorize analysis costs; calendar/image/video budgets cannot authorize them. Requests are idempotent, one active/uncertain analysis per business and at most five per day. Unknown model outcomes remain held, not automatically resubmitted.

Model output must contain bounded proposals, evidence IDs from the exact input, and explicit limitations. Unsupported claims cannot acquire new evidence IDs. The prompt forbids invented results, summing snapshots, ranking incompatible windows or treating correlations as causation. This is not a guarantee of model quality: human review and live quality acceptance remain required. Sample post counts are computed by the UI from actual cited IDs. The application does not promote model confidence to a statistical result.

Migration 036 stores immutable proposed lesson content separately from Brand Brain. Owners/business administrators can approve a hypothesis for testing, reject it, change applicability or retire it through optimistic revisions and append-only review history. These operations do not alter approved product facts. There is intentionally no automatic validated/causal-result state; controlled experiment outcomes remain unfinished work.

New creative/video requests snapshot up to ten approved-for-testing hypotheses; plans and future recurring cycles snapshot them as well. Context is explicitly labelled unproven, never a source of product fact_ids. Workers revalidate the lesson revision and active state before subsequent model/image/video submission. Retiring or changing a lesson blocks stale pending generation, while already submitted provider work retains existing reconciliation semantics. Saved output manifests retain the learning context. No learning crosses business boundaries.

Analytics and Memory share the proposal/evidence/review UI. Creating an analysis is a real queued job; no data or no grant is an explicit error. Read-only teammates can inspect saved lessons; they cannot authorize spending or approve learning. Broader creative-preference examples, source removal, controlled experiment outcomes, richer historical review browsing and live quality verification remain unfinished scope.
