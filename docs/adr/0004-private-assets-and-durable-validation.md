# ADR 0004 — private uploads and durable asset validation

Status: implemented; final local evidence generated by verification gates, not live deployment evidence. This slice accepts brand reference files. It does not extract brand facts or generate creatives.

## Contract and boundary

An authenticated editor reserves a PNG/JPEG/WebP/PDF/PPTX upload with its exact size (maximum 20 MiB) and SHA-256. The server generates the client/brand/asset key; the browser cannot supply a storage key. Reservation is idempotent, with serialized limits of 10 outstanding uploads and 1 GiB active reservations and 1 GiB of reservations per rolling day per brand. Abandoning an unsubmitted upload frees its outstanding slot, but does not reset the daily reservation budget. A 120-second signed PUT grants access to only the quarantine object and signs type and length. Quarantine objects are never downloadable through the product.

Submission atomically queues one validation job, a dispatch record and an audit event. API and database roles cannot mark an asset ready. Dispatch leases start a Temporal workflow with a deterministic ID and reject duplicate workflow reuse; a lost dispatch acknowledgement can reconcile with the existing workflow. History carries organization, brand and job IDs, not file contents, presigned grants or credentials.

The separate worker role requires all three IDs and can access only that job, its asset and its requester's membership. It checks current permission and cancellation before work and again before promotion, sharing the membership-change lock. Worker/dispatcher logins cannot change job ownership, read auth sessions or bypass RLS. Separate storage credentials remain server-side; their bucket-level scope is a trusted-worker boundary, not object-store-enforced per-tenant IAM.

The worker fetches bounded bytes, verifies length/hash, scans with real ClamAV and checks file format. Signature databases older than seven days fail closed. Images are decoded with pixel/dimension limits; PDF/PPTX validation is structural only. A scan does not make arbitrary document content trustworthy: sandboxed Docling extraction remains a separate requirement. Archive metadata limits reject excessive members/expansion, traversal, encryption, symlinks and selected active payloads.

Only the scanned bytes are written to a canonical key ending in their SHA-256. The writer verifies the key/hash/bytes identity and existing content before writing; concurrent permitted writes can only supply identical bytes. Recovery after a lost commit verifies existing canonical content. Garage 2.4.1 was observed to ignore If-None-Match on PUT: the adapter sends it as additional protection on supporting stores, but application integrity does not depend on it. This is not storage-level WORM or protection against compromised bucket credentials. Reusing the old upload URL cannot mutate that canonical file. A fresh authenticated read of a ready asset returns a 60-second signed attachment download. Such bearer grants remain usable until expiry after membership revocation; bucket privacy and exact-key signing are essential. No public bucket policy is installed.

Temporary dependency failures retry up to four validation activities with heartbeats. A real process death is recovered by Temporal. Invalid content is rejected, cancellation/access revocation cancels, and exhausted retry is saved as failed. This retry policy is for local validation: it must not be copied to paid generation or publishing, which require ambiguous-outcome reconciliation. Cleanup failure never turns a valid asset into a failed generation; an orphan/expired-upload reaper and user retry controls remain pending.

## API

Prefix: `/api/v1/workspaces/:org/brands/:brand`.

| Method/path | Result |
|---|---|
| POST uploads | Idempotent reservation and short-lived signed quarantine PUT |
| GET assets | Scoped saved metadata/status; no storage keys |
| POST assets/:id/abandon | Cancel an unsubmitted reservation and recover its upload slot |
| POST assets/:id/complete | Same durable job on repeated submission |
| POST assets/:id/download | Short-lived attachment grant, only after validation |
| GET jobs/:id | Actual durable state, attempts, cancellation and safe error code |
| POST jobs/:id/cancel | Request cancellation; worker records final state |

Migration `003_assets_jobs.sql` adds forced-RLS assets, jobs and job_dispatch. It requires separate NOBYPASSRLS NOINHERIT login roles `desvio_worker` and `desvio_dispatcher`; use secrets-manager passwords. The runtime refuses privileged roles. Migration 000–002 are unchanged.

API storage configuration is S3_ENDPOINT, S3_REGION, S3_BUCKET, S3_ACCESS_KEY_ID and S3_SECRET_ACCESS_KEY. Worker additionally uses WORKER_DATABASE_URL, DISPATCHER_DATABASE_URL, CLAMD_HOST/PORT, TEMPORAL_ADDRESS/NAMESPACE/TASK_QUEUE. `npm run start:worker` runs actual validation and dispatch. Clamd has no authentication: place it on a private network; never expose it publicly. Current Temporal connection is for a private engineering network; production TLS/auth configuration remains a release blocker.

## Verification and dependency sources

Local tests use the real S3 SDK against Garage 2.4.1, the full official ClamAV 1.5.4 signature image, PostgreSQL and Temporal CLI 1.9.1 (embedded server 1.32.0). Test-service digests/archive checksums live in `scripts/storage-test-services.mjs`. ClamAV currently needs amd64 emulation on this arm64 workstation. Tests fail when the pinned signatures become stale; update the reviewed image pin rather than disabling that check.

- [AWS presigned uploads](https://docs.aws.amazon.com/AmazonS3/latest/userguide/PresignedUrlUploadObject.html): grants can be reused before expiry; immutable canonical promotion prevents mutable uploads becoming trusted assets.
- [Garage quickstart](https://garagehq.deuxfleurs.fr/documentation/quick-start/): local single-node service and default private bucket.
- [ClamAV scanning](https://docs.clamav.net/manual/Usage/Scanning.html), [official images](https://docs.clamav.net/manual/Installing/Docker.html): real INSTREAM scanning with supplied signatures.
- [Temporal TypeScript testing](https://docs.temporal.io/develop/typescript/best-practices/testing-suite): local real server and actual workers, no time-skipping or mocked workflow.

Local Garage compatibility does not prove Railway bucket/AWS compatibility, browser CORS, deployed privacy/IAM, scanner operations, disaster recovery, encryption-at-rest configuration or multi-tenant production readiness. Local Temporal 1.32.0 does not prove compatibility with the existing Postiz 1.28.1 infrastructure. No external provider/social call is made by this suite. UI, deletion/retention, quotas per account, observability, parser sandboxing and full generation/publish workflows remain to implement.
