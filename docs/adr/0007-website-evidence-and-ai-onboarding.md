## Fetching and rendering

`safe-web.ts` permits public HTTP(S) business sites, rejects credentials/nonstandard ports/IP-literal/private/special destinations, validates every DNS answer and pins the actual socket lookup. Every redirect is checked. Site pages stay within the supplied hostname/www pair, respect robots rules and crawl delays, and are bounded to five pages, 18 page/robots requests and 2 MiB/page. About/product/service pages are prioritised. Login/cart/checkout/account/search navigation is excluded. Query-bearing asset URLs are permitted only through the same public-address checks.

`website.py` extracts real Crawl4AI source text. `visual.py` additionally renders with real Chromium in a non-root, read-only, capability-dropped container with **no kernel network access, mounted secrets or application credentials**. Every supported browser GET is fulfilled over a bounded stdio broker; unhandled network transports cannot bypass the network namespace. POST, media streams, extra navigation and cross-origin data API requests are blocked. Static public CDN scripts/styles/images/fonts are allowed through the checked broker. No stealth, CAPTCHA solving or account authentication is attempted.

Desktop 1440×1000 and mobile 390×844 captures scroll with overlapping viewports up to twenty-six steps (stopping at the bounded page end), wait for images/fonts within limits, freeze animations and save full-page JPEGs capped at 16000px high. Evidence includes image/currentSrc/alt/loaded state/bounding boxes, inline mark candidates, CSS background imagery, declared typography and actual platform fonts when available, observed colours, section geometry, source links and bounded JSON-LD product/organization information. Counts are observations, not a declaration of approved brand colours/logos or usage rights. Missing resources, cropping and incomplete visual capture are explicit coverage data. Screenshot dimensions and SHA256 are verified before storage.

Resource broker limits: 120 requests, four simultaneous transfers, 2 MiB/resource and a 20 MiB accepted-content budget (bounded in-flight requests may add network bytes); 120-second sandbox wall timeout, 1 GiB memory, one CPU, PID and scratch-space limits. These are bounded first-pass capabilities, not exhaustive-site or universal-rendering guarantees.

## Persistent workflows and tenancy

Migrations 007–009 add website/analysis jobs without fake assets, per-business request keys, operator-only analysis grants, conservative spend reservations, source-linked suggestions, recommendation history, edit protection and private visual evidence. Forced RLS and composite tenant FKs cover every new table. Worker policy separates website ingestion, AI analysis and asset validation; neither app nor worker can grant spending or approve brand facts.

Temporal dispatch uses deterministic workflow IDs and rejects duplicate workflow starts. GET /api/v1/businesses/:id/intake returns saved job/coverage/recommendation/visual metadata. POST submits website.extract or brand.analyze with Idempotency-Key. GET /api/v1/businesses/:id/visuals/:visualId verifies business access before returning a 60-second private signed URL. New visual storage is capped at 256 MiB/business; atomic database insertion preserves source/visual consistency. Blob cleanup after interrupted writes remains an operator/retention task.

Model findings require a valid tenant chunk, exact supporting quote, bounded schema and an unreviewed proposal. Correct/Wrong/Edit remains mandatory; approved profiles are immutable. AI is forbidden to replace already reviewed fields. A draft revision change during a model call rejects application of the outdated result while retaining the provider result. Goals/audience/channels/cadence are persisted **suggestions**, with citations and reasoning. Initial unedited onboarding reads use them automatically; saved user changes win. Later edited/rejected facts or new sources mark prior recommendations stale.

Before any paid request, the worker requires a server key and an enabled, unexpired, operator-provisioned per-business grant with model, audited token rates, budget and approval attribution. A conservative request reservation is recorded **before** submission. All reservations, including unknown/rejected calls, continue counting against the cap. A lost response or interrupted submission becomes unknown; neither workflow retry nor a fresh request can bypass unresolved ambiguity. This is deliberately conservative, not a reconciled billing ledger. Real pricing/account validation and an operator reconciliation UI remain prerequisites.

## Multimodal visual analysis extension

Official [OpenAI vision contract](https://developers.openai.com/api/docs/guides/images-vision) fetched on 2026-10-21 and checked against pinned OpenAI 7.39.0: Responses input messages accept input_text plus input_image with base64 data URLs and detail=high. Image billing differs by model; no universal image-token formula is assumed. Migration 009 adds operator-only max_tokens_per_image (zero by default). The operator must audit a conservative high-detail ceiling for the selected vision model and its input rate; this ceiling is added to the text/output reservation for every image before transmission. Text-only grants cannot silently authorize image spending.

visual-analysis.ts loads at most ten screenshots from the latest committed capture under worker RLS, verifies stored byte length/SHA256/JPEG dimensions and prepares at most thirty images / 12 MiB. Every page gets an overview (maximum 1440×2048); long pages also get a readable header crop and a prominent lower image region or middle crop. Full source screenshots remain stored. Small details in overviews or unsampled regions can be unreadable; this is not exhaustive pixel-level interpretation. Crop coordinates and source/transformed hashes are persisted with the result. No signed storage URL, storage key or screenshot bytes enter saved model results or browser JSON. S3 decoding runs outside transaction locks; membership, cancellation, evidence revision and spend grant are checked again before the call.

Structured visual_guidance separates visible observations from proposed creative directions (composition, imagery, typography, palette, possible marks, inspiration). Each must cite supplied image IDs; unknown/cross-scope references are rejected. No model result automatically changes approved brand facts or establishes image ownership/reuse rights. UI presents suggestions with source references and marks them stale after a newer successful crawl. The browser uses a clearly identified database fixture for this display test. Actual captured pixels and private storage are exercised in the backend suite with a MOCK OpenAI response. Human reference-selection/approval and source-specific model quality evaluation remain next work.
