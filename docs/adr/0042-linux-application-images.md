# 0042 — Verify actual Linux application images before Railway rollout

The web Dockerfile previously copied only web source even though calendar components import browser-safe date helpers and type contracts from the API source tree. Local builds had those files, masking the container omission. The builder now receives that source graph; the final runtime still receives only Next's traced standalone output.

Docker directory re-inclusion also included sibling files beneath allowed parent directories. The upload unexpectedly contained the local ingestion Python environment (677 MB). Explicit child exclusions before re-inclusion reduce the current source context to about 1.6 MB. `scripts/container-context-test.py` builds a scratch image and inspects its actual exported filesystem against the source allowlist, required inputs, forbidden generated/private paths and a 5 MB upper bound. It removes only its own temporary image/container. This check is part of deployment verification.

`make verify-container-images` performs both real Linux amd64 builds, then runs the API's Sharp, Temporal and application imports as UID 1000 with a read-only filesystem, no network, dropped capabilities and resource limits. It starts the actual web image with the same restrictions (loopback-only published port and bounded temporary storage), verifies its narrowly labelled health response and renders sign-in through Chromium. No database/model/social credentials enter builds or these smoke checks. API and web share the dependency-install cache before their build paths diverge.

Generated evidence records image IDs, platform, browser results and source hash. This is packaging acceptance only. A rendered sign-in screen is not proof of connected authentication, SMTP, private media, durable workers or providers. The separate deployment suite covers dedicated local database bootstrap, actual API/standalone proxying and auth; a dev environment exists in Railway, but no Desvio app services/domain or durable isolated worker deployment is claimed here.
