# 0048 — Authenticator MFA through the existing identity provider

Use the pinned Better Auth 1.7.12 `twoFactor` plugin, not a separate authentication system. Contracts were checked against the installed `dist/plugins/two-factor` implementation and the [official two-factor documentation](https://better-auth.com/docs/plugins/2fa) on 2026-10-23. The installed package is authoritative for this build.

Migration 041 adds only the plugin's auth schema: `user.twoFactorEnabled` and `twoFactor` with encrypted secret/backup codes, verification state, failure count and lock expiry. Only the existing auth database role receives access. The SDK migration comparison must report no missing fields/tables/schema problems. Applied migrations are never rewritten.

Authenticator enrollment requires the account password and remains inactive until a valid time-based code is confirmed. Sign-in returns a second-factor challenge and no authenticated application session until TOTP or a single-use recovery code succeeds. Recovery-code replacement invalidates the previous set. Disabling requires the password. Account lockout is five failed second-factor attempts for 15 minutes; the provider additionally throttles its factor routes. No trusted-device option or email/SMS factor is enabled in the customer UI.

Profile renders QR codes locally with pinned MIT `qrcode` 1.5.4 (`@types/qrcode` 1.5.6). The URI/key and recovery codes are held in component memory, never browser persistent storage or an external QR service. A manual setup key is available. Users confirm they saved recovery codes before completing setup. Sign-in supports authenticator and recovery paths while preserving an invitation destination.

Existing authenticated sessions are not automatically revoked by enabling MFA; Profile states that protection applies to future sign-ins and keeps the existing session-management controls. Password reset still uses verified email and the existing session-revocation behavior. Enrollment cancellation discards the UI secret; an unverified provider record does not enable MFA and can be replaced by another password-confirmed enrollment.
