# Natural-language planning and selected-plan follow-ups

Canvas defaults to natural-language planning. The existing original-skill runtime interprets the brief using the selected OpenAI/Gemini planner; no keyword router, guessed endpoint or additional model hop is introduced. The typed output adds exactly three resolved settings in natural mode: 1–90 days, 1–90 posts, and 0–30 videos within the total. All slots must match those settings, allowed channels, the chosen start date/timezone, unique content requirements and current approved fact IDs. Fixed mode retains its existing exact-count contract and rejects a settings override.

The selected saved plan may supply context. The API reads its current edited slots under the same business/role checks and snapshots the plan ID, title, date/timezone, horizon, revisions, briefs and editable video concepts. The bounded snapshot and its hash are stored inside the immutable planning request; clients cannot submit arbitrary context. Oversized context is rejected rather than silently truncated. Model instructions treat it as untrusted creative context, never current evidence for product claims. Current approved brand facts take precedence.

Validated resolved counts become the real persisted calendar horizon and manifest, not merely a prose claim. The manifest records the source plan identity/hash. Follow-ups create a new draft plan, preserving the source plan and its approvals; no implicit overwrites, generation approval or publication occur. UI previews show resolved days/post/video counts and model warnings, and the user can disable selected-plan context or choose explicit counts. Unsaved planning text participates in conversation-switch confirmation.

Recurring charges still require known fixed cycle length/counts, total budget and explicit consent. Natural mode cannot silently create or alter a recurring loop. A request for recurrence receives a model warning directing the user to fixed-cycle controls. Original provider limits, unknown-call holds, exact skill pins, job durability and tenant isolation remain unchanged. Rebuild the existing isolated skill image when deploying this runtime change; no new credential or migration is required.

Verification uses the actual original skills and local database with MOCK model responses. It covers bounded settings, rejection of fabricated facts or action fields, edited source context, cross-business denial, immutable source preservation, correct persisted horizons and no implied video generation. Browser verification covers a natural weekly follow-up using Gemini's official SDK with MOCK responses. Live language interpretation/output quality, general intent routing across all Canvas operations, direct creative provider selection, video publishing and deployment remain open.
