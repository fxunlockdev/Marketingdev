# ADR 0022 — Original video skills and isolated MP4 normalization

Status: implemented and locally tested components; parent workflow, deployed image and live acceptance pending. Original architecture retained: Deep Agents uses the owner's archive, Higgsfield generates/edits video, and private media processing remains isolated. No customer feature or new provider is enabled here.

## Decision and contracts

`apps/api/src/video-planning.ts` and `SkillRuntime.videoPlan` require approved fact IDs/hash and owned-reference metadata without locations or credentials. Actual original video/ad-creative/product-marketing/social Markdown is loaded by Deep Agents 0.7.29. The original video skill digest is `0a35e32dda553707996bf383c00ecf971d05127d35d5d814577457c23a3ab591`, tree `76696e47ce406b06143b50a08d75effa0a5dfd109f12beb86fd5e3d1b68900f1`. Only read_file on selected immutable Markdown/context is available. Tool/helper/vendor suggestions inside skill documents cannot change the platform's provider boundary. Tests inspect the actual non-root, read-only, network-disabled container and verify original reference reads, context separation, denied tools and bounded broker calls. The model is MOCK; structural fact-ID validation is not proof of semantic truth or creative quality.

The brief describes one continuous 3–15-second clip, exact contiguous timed beats and up to three non-overlapping same-position text overlays. Overlays are editable instructions; neither the planner nor this PR's decoder renders them. Read/version/digest evidence must match the selected original skills. The existing static-image and thirty-day planning branches run through the changed actual runtime as regression tests.

`apps/video/runtime.py` accepts bytes plus hash and requested duration, never URLs/paths/commands. Supported short SDR MP4 is fully decoded/re-encoded, metadata-stripped, probed and fully decoded again before returning canonical H.264/AAC and poster bytes. Strict media limits and unsupported color/orientation refusals are documented in `apps/video/README.md`. No saved asset, provider completion, successful product job or publishing approval is inferred from these bytes.

FFmpeg's documented MOV options disable external tracks; explicit stream mapping and error termination constrain normalization. See [MOV demuxer options](https://ffmpeg.org/ffmpeg-formats.html#mov_002fmp4_002f3gp), [FFmpeg options](https://ffmpeg.org/ffmpeg.html) and [ffprobe](https://ffmpeg.org/ffprobe.html). Rotation fixtures use the documented input display_rotation override; a stream-copy metadata flag did not create the intended fixture. HDR fixtures encode actual transfer metadata rather than relying on an ineffective stream-copy label.

## Dependency and execution evidence

FFmpeg `7:7.1.5-0+deb13u1` is acquired from signed official Debian trixie/trixie-security indexes ([package](https://packages.debian.org/trixie/ffmpeg)). `apps/video/debian-arm64-packages.json` pins all 201 downloaded archive hashes/versions. The offline extraction script verifies every archive before extraction, accepts bounded regular files/relative in-bundle symlinks only, retains copyright notices and never runs maintainer scripts. No host FFmpeg parses provider or fixture bytes.

The actual skill image builds successfully using cached dependencies: `sha256:c632db82d0fec3a18dfb5a0d8f9e3dbcfcf86ad8d02f363853be539cc62f16d2`. This does not resolve the separate full document-image storage blocker. No unrelated container was stopped, pruned or restarted.

The FFmpeg test uses the exact Python base and read-only verified bundle/runtime mounts with a non-root user, no network/capabilities/privilege escalation, 64 PIDs, 2 GiB memory, one CPU and 256 MiB temporary filesystem. This proves bounded actual decoding in that test boundary, **not a built/deployed video image or AMD64 service**. The stage is intentionally unregistered. Reproducible dependency acquisition, deployment image/architecture, adapter and distribution obligations (the Debian build enables GPL) remain open.
