# ADR 0039: saved organic post metrics

Use the pinned Postiz post analytics endpoint through the existing authenticated transport, verifying remote organization on every request. The existing durable publication reconciliation activity requests metrics only after matching the saved post ID, channel, caption and schedule and confirming a published release. No new queue or customer-facing provider interface is introduced. The current publishing connector still supports LinkedIn personal accounts; providers without metrics correctly return unavailable. Page/channel expansion remains separate work.

Migration 035 stores append-only per-business observations with the exact publication and job IDs, provider, collection time, measurement semantics, series and bounded error code. App users cannot insert or update metrics. Worker access is restricted to the current publication job/check. A failed metrics fetch records an error separately and does not downgrade a confirmed publication or delete historical observations. Reconciliation remains explicit/rate-limited; metrics errors do not trigger a new publication.

The transport validates bounded dated numeric series, rejects duplicate labels/dates and invalid dates/values, strips unknown properties and does not use upstream percentageChange. Empty/missing/error data stays distinct from zero. The UI renders individual reported observations, never sums snapshots or describes them as daily gains. Only a separately audited provider may declare lifetime semantics. Current personal LinkedIn metrics have unspecified measurement semantics and are labelled accordingly; the pinned provider currently lacks postAnalytics support, so real results will normally be unavailable there.

GET /api/v1/businesses/:id/analytics filters confirmed published posts by UTC publication dates, channel and static/video format, with a 100-post bound. It does not claim to change the provider measurement window. Read access follows existing business permissions, including read-only teammates; refreshing remote status remains administrator-controlled. The customer view polls saved data and offers an explicit saved-data refresh.

This delivers collection/storage/display, not the complete Analytics module. AI comparisons, metric definitions, campaign filters, historical observation browsing, supported Page/social connectors, and approved learning/Memory remain unfinished. Local HTTP, database, durable-job and browser tests use MOCK upstream Postiz responses; no real metrics or live publishing are claimed.
