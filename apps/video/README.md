# Video normalization component

Internal, unregistered stage. No customer route, worker adapter or production image is enabled by these files. `runtime.py` accepts one bounded JSON line containing MP4 bytes, their expected SHA-256 and an integer duration (3–15 seconds). It returns canonical MP4 and PNG poster bytes/hashes, or a sanitized error. It neither approves nor persists media. Timed overlay plans are validated separately; this component does not composite them yet.

The first supported profile is one H.264/HEVC 8-bit SDR video track, optional one AAC mono/stereo track, 1–60 fps, dimensions 64–4096 with at most 8,388,608 pixels, duration within 250 ms of the request and no display transform. Other streams, HDR/10-bit, unknown formats and orientation transforms are refused. Accepted media is completely decoded and re-encoded to H.264/yuv420p at 30 fps with AAC when audio exists, bounded to a 1920-pixel long side and 1080-pixel short side, then completely decoded again. Original metadata is removed; a thumbnail alone is never evidence that the full clip is valid. Actual provider eligibility and quality remain unverified.

Only fixed executable/argument profiles are used. There are no customer filenames, URLs, filters, fonts, shell commands or credentials. The MOV demuxer has external references disabled and only the file protocol; parsing belongs inside the network-disabled, non-root, read-only, capability-free sandbox with bounded memory/CPU/PIDs/tmpfs. Subprocesses have deadlines, limited allocation/output, and sanitized failures. Stdio startup adds CPU/file limits and an overall deadline. These controls reduce risk; they do not claim proof against all decoder vulnerabilities.

## Reproducing the focused local test

`make verify-video-runtime` builds the actual pinned Deep Agents image, tests the original video skills with a MOCK model, verifies the SHA-256 of every local Debian archive against `debian-arm64-packages.json`, safely extracts the required binaries/libraries/fonts/license notices without package scripts, and runs actual FFmpeg tests inside the pinned Python container. Synthetic clips are generated and parsed only inside that container. Temporary test containers and extracted bundles are cleaned up.

The default archive cache is `work/video-deps-arm64/debs`; `DESVIO_VIDEO_DEB_CACHE` can select another build cache. Missing or changed archives fail verification. This is developer verification, not the final operator provisioning flow. To acquire the initial cache, APT in the exact Debian 13 ARM64 Python base verified the signed trixie/trixie-security indexes from `https://deb.debian.org/debian` and `https://deb.debian.org/debian-security`, then downloaded (without installing) `ffmpeg=7:7.1.5-0+deb13u1` and fonts-liberation plus dependencies. The 201 exact archive versions and hashes are pinned. Future acquisition must resolve those pins through signed official indexes or a verified snapshot; it must not silently upgrade them. The host extraction tool uses only verified archives, never runs package scripts and does not invoke host FFmpeg.

Local Docker storage is constrained. Tests therefore mount the verified dependency bundle and runtime read-only into `python:3.12-slim@sha256:a6e34c598f2467ed0e9a8d349809fcd8b5c603269512df273a0bb1784edc11b1`, with no network, no secrets and only ephemeral writable `/tmp`. This accurately tests the decoder code and sandbox restrictions, **not a baked deployment image**. No application adapter may substitute an arbitrary host bind mount for a production image. ARM64 proof is not AMD64/Railway proof.

The Debian build enables GPL components including libx264. Upstream copyright/license notices are retained in the extracted bundle. Distribution/source-offer obligations, a reproducible automated dependency acquisition path, vulnerability review, deployment-architecture image builds and exact image attestation remain release blockers. Do not describe the dependency as having no licensing constraints.
